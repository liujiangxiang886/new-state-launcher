# 使用手册（新起点启动器 1.7）

> 面向玩家与整合包发布者。扩展作者请看 `扩展开发文档/`。

---

## 1. 界面总览

| 区域 | 作用 |
|---|---|
| 左侧版本下拉 | 切 4.6 / 4.7 / 自定义版本；**切版本 = 切整条线的 mod 与存档** |
| 游戏库 | 启动、实例状态、mod 列表、存档 |
| 扩展管理 | 导入、启用/停用、卸载、冲突检查、整体校验 |
| 设置 | 引擎路径、源码目录、校验档、帧率上限、开发者模式、清理残留 |
| 底部日志 | 每次操作的结果；出错先看这里 |

---

## 2. 第一次使用

1. **导入本体**
   - 4.6：设置 → 引擎/本体 → 选择 1.45 原版的 exe（或 pck）。
   - 4.7：选择标准 4.7 的 pck（**380,259 条目**）。
2. 启动器会计算本体指纹，用于源码兜底与补丁校验。
3. 选版本 → 点「启动」。能进游戏再开始装 mod。

> 4.7 如果不是标准本体，会提示「pck 大小与随包源码不符」。这是保护：
> 源码对不上时补丁可能打错位置。换标准本体，或在设置里指向匹配的反解工程。

---

## 3. 安装扩展

### 3.1 支持的形式

| 形式 | 说明 |
|---|---|
| 单个扩展 zip | 根目录有 `extension.json` |
| 合集 zip | 里面是多个扩展 zip，外层没有清单 |
| `.jjm` / `.pack` | 与 zip 同构，改扩展名而已 |

拖进窗口即可；也可以「导入扩展」多选。

### 3.2 导入期间不能启动游戏

点下导入会先弹一个提示：

> 这可能需要一些时间进行导入，在此期间无法启动游戏。

确认后进入导入，**启动按钮会变成「导入中…」并禁用**，游戏库页的「启动游戏」
同步禁用；导入完成（或失败退出）后自动恢复。

- 单包通常几秒到半分钟；21 个包的合集在完全校验下约 1 分钟
  （装完统一跑一次运行校验，不再逐个包各跑一遍）。
- 反过来也拦：**游戏正在运行时不能导入**。运行中的实例已经握住了覆盖层
  文件句柄，此时改写它不会生效，只会得到「装了没反应」。先退出游戏再导入。

### 3.3 安装目标

**永远装到当前选中的版本线。** 装之前先确认左上角是 4.6 还是 4.7。

- 4.6 的包拖到 4.7 → 直接拒绝：「只适配 4.6」。
- 要两线都装 → 分别切到两条线各导入一次（作者需提供两份包）。

### 3.4 安装结果怎么看

| 状态 | 含义 | 下一步 |
|---|---|---|
| 待插桩 | 文件装好，钩子待插 | 启动一次游戏 |
| 已就绪 | 文件完整，可挂载 | 正常玩 |
| 已剔除 | 开发者模式判定有问题 | 看原因，或切宽松档 |
| 不在此线 | 不是当前线的包 | 切版本 |

> 首次导入的「待插桩」是流程的一部分，不是失败。

## 4. 启用 / 停用 / 卸载

### 4.1 启用与停用（按线）

- 每行右侧「停用 / 启用」只改**当前线**。
- 同一个包在 4.6 停用、4.7 仍启用，是正常状态。
- 游戏运行时不能改；先退出游戏。

### 4.2 卸载（按线）

- 单行「卸载」：如果包装在多条线，会问你：
  - **只卸载当前线**：另一条线的覆盖层与启用状态保留；
  - **全部卸载**：删整个包目录。
- 批量卸载（底部按钮）默认全卸。
- 卸载会清该线的插桩缓存；没清干净时用「清理残留」。

---

## 5. 启动与实例

- 默认单实例；开发者版可多开（每个实例独立存档目录）。
- 启动失败会弹「诊断码 + 日志路径」，先看日志。
- 3 秒内秒退判定为启动失败；自动兜底会尝试停用可疑扩展并重启一次。
- 启动成功 5 秒后，本次插桩成功的扩展状态从「待插桩」变「已就绪」。

### 5.1 校验档

| 档 | 行为 | 给谁用 |
|---|---|---|
| 宽松校验 | 全套检查照跑，问题提示但照装 | 玩家默认 |
| 完全校验 | 有 error 就拒装；启动前确认剔除名单 | 作者 / 开发者 |

设置 → 扩展校验档切换。作者发布前必须用完全校验跑一遍。

---

## 6. 存档

| 功能 | 位置 |
|---|---|
| 存档列表 | 游戏库 → 存档 |
| 自动备份 | `profiles/<名字>/.history/<时间戳>/` |
| 导入存档 | 存档页 → 导入（导入前自动备份） |
| 导入角色 | 支持从别人的存档导入单个角色 |

- 每条线/每个实例的 `user://` 目录不同，不会串档。
- 不要手工删 `profiles/`；用界面删除会保留历史。

---

## 7. 4.7 剧情覆盖层

- 游戏库 → 4.7 → 「4.7 剧情覆盖层」。
- 「替换剧情包…」：选一个 `.pck`（脚本/场景/数据），旧文件备份为 `story.pck.bak`。
- 替换后，按旧剧情源码算锚点的 mod 可能失配——界面会警告。先停用该线扩展再换层。
- 剧情包不是扩展：不参与启用/停用，删它用「删除该线扩展」或手工移除登记。

---

## 8. 自定义版本

- 游戏库 → 管理自定义版本 → 添加，选择改版的 exe 或 pck。
- 启动器按内容自证身份，不采信描述里的版本声明。
- 只启动、不挂 mod；想支持 mod 需要创作者交付反解源码基线（见开发文档）。
- 存档目录独立；卸载登记不会删你的游戏文件。

---

## 9. 清理与诊断

| 操作 | 位置 | 作用 |
|---|---|---|
| 清理残留 | 扩展管理 → 清理残留 | 注册表过期条目、孤儿目录、失效插桩缓存 |
| 整体校验 | 扩展管理 → 整体校验 | 真跑一次引擎，核对每个包是否装载 |
| 导出诊断 | 设置 / 错误弹窗 | 打包日志与配置，便于反馈 |
| 重置界面 | 设置 | 恢复布局与主题，不动扩展与存档 |

---

## 10. 速查

```text
装 mod：选版本 → 拖入 → 看状态
生效：启动一次 → 等 5 秒 → 已就绪
停用：只影响当前线
卸载：多线包会问「只卸当前线 / 全部」
换线：左上角下拉；mod 与存档一起换
出错：先看日志最后 20 行
```
