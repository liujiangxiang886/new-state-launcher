## 1. 分线隔离

### 1.1 数据模型

注册表 `config/extensions.json`：

```jsonc
{
  "items": [{
    "id": "me.mod",
    "enabled": true,          // 镜像：任意一条线启用即为 true（兼容旧代码）
    "engine_line": "4.7",     // 镜像：最近一次安装的线
    "status": "ready",        // 镜像
    "lines": {
      "4.6": {
        "line": "4.6",
        "overlay": "packs/me.mod/overlay-46.pck",
        "status": "needs_hooks",
        "enabled": false,     // ★ 真正的启用位
        "hooks_verified_at": "",
        "sources": { "name": "sources-4.6.zip", "sha256": "…", "line": "4.6" }
      },
      "4.7": { "…": "…" }
    }
  }]
}
```

- `lines` 是**唯一真值**；顶层字段只是兼容镜像。
- 老数据没有 `lines` 时，读取方按 `engine_line` 单线处理（`enable.enabled_mods`、
  扩展页 `_item_on_line`）。
- 旧 `lines` 条目没有 `enabled` → 默认 `True`。

### 1.2 关键函数

| 位置 | 作用 |
|---|---|
| `service.install(target_line=…)` | 只写目标线的覆盖层/清单；跨线硬拒绝 |
| `service.set_enabled(…, line=…)` | 只改 `lines[line].enabled`，重算顶层镜像 |
| `service.uninstall_line(ids, line)` | 只删该线文件；`lines` 空了才删目录 |
| `service.mark_launched(line, ids)` | 该线「待插桩 → 已就绪」 |
| `enable.enabled_mods(cfg, line)` | 按线裁剪；检查 `picked.enabled` |
| `paths.line_tag(line)` | 文件名安全化（`custom:abc` → `custom_abc`） |

### 1.3 不变量（改代码时必须保持）

1. **任何按线命名的文件都必须过 `paths.line_tag()`**。直接用
   `line.replace(".", "")` 在自定义线上会生成带 `:` 的非法路径。
2. **顶层 `enabled` 不能单独决定是否加载**。只看顶层会让 4.6 的停用把 4.7 也关掉。
3. **重装一条线不能重置另一条线的启用位**。`install` 里顶层 `enabled` 按 `lines` 求 OR。
4. **卸载一条线不能删整目录**，除非 `lines` 为空。
5. **插桩缓存按线归属**（`cache/instrumented/*.json` 的 `line` 字段），卸载/版本变化只清本线。

### 1.4 界面

- 扩展页只渲染当前线的条目；行内状态读 `lines[current].status/enabled`。
- 卸载多线包：`_ask_uninstall_line` → 「只卸当前线 / 全部 / 取消」。
- 游戏库的启停同样传当前线（`library._toggle_mod`）。

## 2. 源码兜底

### 2.1 文件

```
baseline/sources-4.6.zip + sources-4.6.json   # 109 个 .gd + 本体指纹
baseline/sources-4.7.zip + sources-4.7.json   # 138 个 .gd + 本体指纹（380259）
baseline/canonical_sources.zip                # 旧名，仍兼容（仅 4.6）
```

`basecontent.canonical_zip(line)` 优先线专属名。`canonical_mismatch` 按
sha256 > exe_size > pck_size > entry_count 判定；**信息缺失不阻断**。

### 2.2 取原文优先级

`BaseContent`：反解工程 → 剧情覆盖层（4.7）→ 基线 pck 明文 → 随包源码 →
已安装扩展覆盖层（可关）。

插桩与补丁都走它，所以「启动器自动使用源码」不是一句口号，而是所有路径的唯一入口。

**反解工程必须先按引擎线匹配**（`source_root(cfg, line)`）：

```python
# ① 该线自己登记的工程优先
meta = (cfg.get("runtime_sources") or {}).get(line) or {}
if meta.get("project_godot") and Path(meta["project_godot"]).exists():
    return Path(meta["project_godot"]).parent

# ② 退而用 sources.reversed_project，但要用 project.godot 校验归属
actual = _project_engine_line(root / "project.godot")   # 读 config/features 首项
if actual and actual != line:
    return None                                        # 是别条线的工程，拒用
```

判断依据只认 `project.godot` 里 `config/features=PackedStringArray("4.7", ...)`
的首项 —— 目录名、配置键名都不可信。读不出 features 时保持旧行为（信任配置），
避免把没写 features 的合法工程挡在门外。

> **历史坑（2026-11-13 修）**：`source_root` 曾无条件优先 `reversed_project`，
> `line` 参数完全没被使用。本机该项指向一个 **4.7 的**反解工程，于是**所有 4.6 线
> 校验都在跟 4.7 源码比锚点**（`game.gd` 66 KB vs 117 KB、`hud.gd` 18 KB vs 32 KB），
> 27 个原生 4.6 包里有 9 个被报「命中 0 处 / 部分兼容」——全是假警报。
> 修复后这 27 个包在 4.6 线 **27/27 全部兼容**，装备兵工厂的文本补丁从 1/8 回到 8/8。

### 2.3 闸门

| 位置 | 条件 | 行为 |
|---|---|---|
| `service.install` | `m.needs_source` 且 `source_ready()` 失败 | `install.no_source` 拒装 |
| `manifest._validate_sources` | schema 4 缺 `sources`；sha/line 不符 | error |
| `enable.build_for_launch` | 有钩子但插桩层为 None 且源码不可用 | `LauncherError` 中止启动 |
| `enable._build_instrumented` | 单脚本找不到原文 | 警告 + 跳过（不整包失败） |

`source_ready` 的逻辑：有反解工程 → 可用；否则要有 zip 且指纹不冲突。

### 2.4 声明校验

- `manifest.normalize` 解析 `sources`（字符串或对象）；
- `_validate_sources` 只在 `needs_source` 时检查；
- schema ≤3 缺失 → warn；schema 4 缺失 → error；
- `sha256` 对比 `basecontent.source_info()`（按文件 mtime 缓存，避免每次装包重算）。

### 2.5 状态流转

```
install: 有 method_hooks → status=needs_hooks
launch:  _build_instrumented 返回 applied 脚本集
         → LaunchMods.ready_ids = 声明钩子的目标脚本 ⊆ applied 的包
         → 进程稳定 5s（或正常退出且运行 ≥5s）→ service.mark_launched
         → lines[line].status=ready + hooks_verified_at
```

缓存的 `.json` 里新增 `applied` 字段；命中缓存时按它判断，不能用请求集代替
（源码缺失的脚本会被跳过）。

## 3. 打包工具（tools/jjm_pack.py 1.7）

- `SPEC_VERSION=1.7`，支持 schema 4；
- `manifest` 子命令自动写 `sources`（读本机 `sources-<line>.zip` 算 sha256）；
- `check` 新增 `SRC-00..06`；`SELF-01` 前先按随包源码判定（`SELF-04`）；
- `verify` 复用 `check`，SRC-01 等 error 会进 `ADM-02`；
- `seal` 的 `verification.json` 仍由 `jjm_pack seal` 生成，缺它开发者模式不认。
