## 0. 一句话结论

- **权利产生不靠登记**：著作权自作品创作完成之日自动产生（《著作权法》第二条、《著作权法实施条例》第六条）。登记是自愿的，作用是「权属的初步证据」，不是取得权利的前提。
- **但「生成瞬间就归我」不准确**：AI 辅助产出的可版权性，取决于能否证明你付出了**实质性独创性智力投入**（需求、架构、指令迭代、筛选、修改、整合、验证）。证据越完整，主张越稳。
- **本项目证据强度：高**（见第 1 节）；**真正的风险不在 AI 代码归属，而在游戏本体/第三方扩展的授权、以及发布目录夹带的私有数据**（见第 3 节）。

## 3. 需要优先处理的风险（比「AI 代码归谁」更实际）

### 3.1 游戏本体与第三方扩展的授权 ⚠️ 最高优先级

- `runtime/host46/jjxf46.exe`、`baseline/` 均源自《机甲旋风》原版及 Godot 引擎。
- **随包的 Godot 4.6 引擎是 MIT 许可**，但 MIT 要求**保留版权与许可声明**；当前 `runtime/` 目录下**没有 LICENSE/COPYING 文本** → 需补（从 Godot 官方仓库取 `LICENSE.txt`）。
- 原版游戏程序、美术、剧情、角色的著作权归原权利人。「不含游戏本体」「免费分享」能降低商业侵权主张，但：
  - **免费 ≠ 不侵权**；
  - mod / 扩展可能构成对原作的**演绎作品**，未经许可的分发仍有风险；
  - 还可能涉及规避技术措施、不正当竞争等。
- 现有文档已写明「仅提供 mod 扩展内容、不含游戏本体」「免费开放分享」，方向正确，**但建议单独做一次授权风险评估**。

### 3.2 发布目录夹带私有数据 ⚠️ 发布前必须清理

`dist/机甲旋风兼容启动器/` 实测包含：

| 目录 | 大小 | 风险 |
| --- | --- | --- |
| `packs/` | 367MB / **19 个扩展** | 含 `mch.*`、`qt6663.*`、`story-官方分区-轻量`、`test.member` 等，多为第三方/私有扩展，随包分发需各自授权 |
| `profiles/` | 13MB | 含 `default`、`diag46`、`locktest46`、`scene_*` 等**测试存档/进度档位**，可能含玩家或测试数据 |
| `builds/`、`cache/`、`logs/` | 16MB / 287KB / — | 构建中间产物、运行日志，可能含本机路径 |
| `config/extensions.json` | 196KB | 含本机扩展启用状态与**本机路径** |

> **对外发布前**：删掉 `packs/`、`profiles/`（或只留空结构）、`builds/`、`cache/`、`logs/`，
> 并把 `config/` 重置为不含本机路径的默认模板。发布包应只含：exe、`_internal/`、`runtime/`、
> `engines/`、`baseline/`、`schemas/`、干净的默认配置。

### 3.3 名称与品牌

- 「机甲旋风」为原游戏名称，用于启动器名称/窗口标题存在商标与来源混淆风险。
- 「柳江巷」是你的创作者标识（源码内 `AUTHOR`/品牌区），可保留。

## 4. 关于「要不要登记」的操作清单

登记自愿。若决定办理**计算机软件著作权登记**（中国版权保护中心）：

- [ ] 准备：申请表、源程序（前后各 30 页，共 60 页；不足 60 页全部提交）、设计说明书或用户手册、身份证明。
- [ ] **如实申报开发方式**（AI 辅助），不要虚报「全部独立开发」。
- [ ] 同步归档第 1.3 节的创作过程证据——登记证书只是**初步证据**，可被反证推翻。
- [ ] 若只为自用/小范围免费分享：不登记也完全可以，把证据留好即可。
- [ ] 若打算公开分发、上架、商业化或担心被抄：登记是有性价比的「证据保险」。
