# 4.6 线 · 1.45 原版 mod 开发规范

> 适用：**新起点启动器 1.7** · 4.6 引擎线（机甲旋风 1.45 原版 · Godot 4.6）
> 基线：`jjxf.v1.45`　清单：`extension.json`（`manifest-46.v2.json` 也认）
> 规范版本：**1.7**（schema **4**）　配套工具：`tools/jjm_pack.py`

---

## 0. 先记住五条铁律

1. **一条线一份包**。4.6 的包只能装到 4.6；装到 4.7 会被硬拒绝（补丁锚点不同，跨线重算会静默失效）。
2. **一个包一次只装一条线**。同一个包可以分别出 4.6 / 4.7 两份，但覆盖层、启用状态、卸载互不影响。
3. **补丁与钩子必须声明源码**。用了 `text_patches` / `method_hooks` 的包，`sources` 必填（schema 4）。启动器**自动**用 `baseline/sources-4.6.zip` 兜底，你不需要把原版脚本打进包里。
4. **首次导入显示「待插桩」是正常的**。插桩在启动游戏时做；启动成功 5 秒后自动变「已就绪」——那才代表钩子真的注册上了。
5. **不要用 `files[]` 铺原版 `scripts/*.gd`**。那会整片盖掉别人的补丁，也会让插桩基底错位。要改脚本用 `text_patches`。

## 1. 适用范围

| 项目 | 取值 |
|---|---|
| 引擎线 | 仅 `4.6` |
| 基线 id | `jjxf.v1.45`（别名 `jjxf.v1.45.original` 也认，两个名字指同一条线） |
| 清单 schema | 1 / 2 / 3 / 4；**新包写 4** |
| 包格式 | `.zip`（`.jjm` / `.pack` 同扩展名，内容必须一致） |
| 安装位置 | `packs/<扩展 id>/overlay-46.pck` + `manifest-46.v2.json` |
| 校验档 | 玩家版默认宽松；开发者版默认完全校验。**作者发布前必须跑完全校验** |

### 1.1 4.6 与 4.7 为什么不能混

| 事实 | 4.6 | 4.7 |
|---|---|---|
| 本体 | 1.45 原版，`pack_version=3` | 剧情版，`pack_version=4` |
| `scripts/hud.gd` | 18,011 字节 | 32,067 字节（剧情改写） |
| 源码层 | `baseline/sources-4.6.zip`（109 个脚本） | `baseline/sources-4.7.zip`（138 个脚本）+ 剧情覆盖层 |
| 补丁锚点 | 按 4.6 源码算 | 按 4.7 源码算 |

同一个 `find` 字符串在两条线上**都可能命中**，但命中的函数可能不是同一个——这是跨线包最危险的地方，启动器对此是硬拒绝，不是警告。

## 2. 源码兜底：为什么必须声明 `sources`

`text_patches` 改的是**脚本文本**，`method_hooks` 要往**函数体里插桩**。两者都必须先拿到原文。

原版 pck 里的脚本是编译后的 `.gdc`，**改不了**。所以启动器随包带了一份反解源码：

```
baseline/sources-4.6.zip     ← 109 个 .gd，1.45 原版
baseline/sources-4.6.json    ← 本体指纹（exe_sha256 / exe_size / entry_count）
```

启动时按下面顺序取原文（`app/core/ext/basecontent.py` 的 `SourceReader.read`）：

1. 设置里指向的反解工程（作者本机调试用）
2. 剧情覆盖层（**只有 4.7 有**，4.6 跳过这一层）
3. 基线 pck 里本来就以 `.gd` 形式存在的文件（排在随包源码**前面**：玩家本体自带源码时，
   那才是这台机器的真实版本）
4. **随包源码 `sources-4.6.zip`**——绝大多数情况走这一层
5. 已安装扩展的覆盖层（仅用于「给别人的 mod 打补丁」）

> 记法：**自己的反解工程 > 这条线的真实内容 > 本体自带源码 > 随包兜底 > 别人的覆盖层**。

### 2.1 清单怎么写

```jsonc
{
  "schema": 4,
  "sources": {
    "name": "sources-4.6.zip",
    "sha256": "把 tools/jjm_pack.py manifest 生成的值原样保留",
    "line": "4.6"
  }
}
```

- `sha256` 与启动器随包源码不一致 → **安装期直接拒绝**（说明你是按另一份源码算的锚点）。
- schema 4 没写 `sources` → 拒绝；schema ≤3 没写 → 只警告（存量包兼容），但发布新包不要这么干。
- 用 `python tools/jjm_pack.py manifest 你的目录 --id me.xxx --name "名字" --line 4.6` 自动写入，不用手抄哈希。

### 2.2 启动器的硬闸门

| 场景 | 行为 |
|---|---|
| 本机没有该线源码，且包要用补丁/钩子 | **拒绝安装**，提示补源码或指向反解工程 |
| 随包源码与本机本体指纹不符 | **拒绝安装**（补丁会打错位置） |
| 启动时发现已装包要插桩，但源码没了 | **中止启动**，明确告知缺什么 |
| 纯 `files` / `data_patches` 包 | 不需要源码，正常安装 |

## 3. 包结构

### 3.1 单包

```
我的扩展-1.0.0.zip
├─ extension.json          ← 清单（必须在根目录）
├─ payload/                ← 载荷，名字随意，靠 files[] 映射
│   ├─ mods/me.my_ext/
│   │   ├─ main.gd
│   │   └─ data/rules.json
│   └─ assets/...
└─ README.md               ← 可选
```

### 3.2 合集包

```
合集-2026.11.zip
├─ me.mod_a-1.0.0.zip
├─ me.mod_b-2.1.0.zip
└─ me.mod_c-1.3.0.zip
```

外层**不能有** `extension.json`。1.7 起合集允许部分成功：某个成员装不上，其余照装。

## 4. 清单字段

```jsonc
{
  "schema": 4,
  "id": "me.my_ext",
  "name": "我的扩展",
  "version": "1.0.0",
  "kind": "extension",
  "author": "你的名字",
  "baseline": { "id": "jjxf.v1.45", "engine": { "line": "4.6" } },
  "sources": { "name": "sources-4.6.zip", "sha256": "…", "line": "4.6" },
  "priority": 50,
  "requires": [],
  "conflicts": [],
  "load_after": [],
  "claims": [],
  "files": [],
  "data_patches": [],
  "text_patches": [],
  "method_hooks": []
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | ✅ | 新包写 `4` |
| `id` | ✅ | `^[a-z0-9][a-z0-9._-]{1,63}$`，全局唯一 |
| `name` / `version` | ✅ | 展示名可中文；版本 `x.y.z` |
| `baseline` | ✅ | `id` + `engine.line=4.6` 必须自洽 |
| `sources` | ✅（有条件） | 用了 `text_patches` / `method_hooks` 就必须写 |
| `kind` | 建议 | `extension`（默认）/ `minigame` / `theme` / `framework` |
| `priority` | 否 | 默认 50，越小越先加载 |
| `requires` | 否 | **离开它就坏**才写；缺依赖会拒绝启动 |
| `conflicts` | 否 | 明确不兼容的 id |
| `load_after` / `load_before` | 否 | 只影响顺序，不构成依赖 |
| `claims` | 否 | 声明占用的业务规则，见 `docs/claims能力占用约定.md` |
| `scripts.entry` | 否 | 运行期入口；纯覆盖层包可以不写 |

未识别字段会被保留并提示；自定义字段请用 `x_` 前缀。

## 5. 四种改动方式（按稳定性排序）

### 5.1 `files[]` —— 整文件铺入（最稳，优先用）

```jsonc
"files": [
  { "source": "payload/mods/me.my_ext/main.gd", "target": "mods/me.my_ext/main.gd" },
  { "source": "payload/assets/icon.png", "target": "assets/ui/icon.png",
    "expect": { "sha256": "改之前那个文件的哈希" } }
]
```

- 只放**自己的新文件**，或明确要替换的**资源**。
- `expect` 用来断言「改之前是什么」，不匹配时按 `on_miss` 处理，不会静默改错。
- **禁止**用它铺 `scripts/*.gd`（见铁律 5）。

### 5.2 `data_patches[]` —— 改 JSON 里的一个值（次稳）

```jsonc
"data_patches": [{
  "target": "data/equipment.json",
  "operations": [{
    "op": "replace",
    "path": "/catalog/100001/attack",
    "expect": 120,
    "value": 150,
    "on_miss": "abort"
  }]
}]
```

- `path` 是 JSON Pointer；`expect` 断言旧值。
- 能改数据就别改脚本——数据补丁不受源码版本影响。

### 5.3 `text_patches[]` —— 改脚本文本（要重算锚点）

```jsonc
"text_patches": [{
  "target": "scripts/skill_panel.gd",
  "find": "\tvar max_level := 10\n",
  "replace": "\tvar max_level := 20\n",
  "expect_count": 1
}]
```

四条硬规则：

1. `find` 在搜索范围内必须**恰好**出现 `expect_count` 次（默认 1）。
2. 缩进逐字符一致（原版是 Tab，不是空格）。
3. `find` 和 `replace` 要**一起改**；只改 `find` 会把旧内容写回去。
4. 锚点不唯一时用 `scope` 收窄到函数：

```jsonc
{ "target": "scripts/pet_state.gd", "scope": "function:open_package",
  "find": "\tif not persist(before):\n\t\treturn {}\n",
  "replace": "\tif not persist(before):\n\t\treturn {}\n\t# patched\n" }
```

### 5.4 `method_hooks[]` —— 挂到方法上（不用改原文）

```jsonc
"method_hooks": [
  { "target": "scripts/game.gd", "method": "combat_power", "phase": "after" }
]
```

- 启动器在启动时把 `dispatch_before` / `dispatch_after` 插进方法体，生成 `instrumented.pck`。
- 方法名写错不会报错，只是钩子不触发——所以**必须**用 `jjm_pack.py check` 对源码核一遍。
- 钩子目标脚本必须在 `sources-4.6.zip` 里；找不到就保持「待插桩」，不会假装成功。

## 6. 状态：待插桩 → 已就绪

| 时机 | 界面状态 | 含义 |
|---|---|---|
| 刚导入 | **待插桩** | 文件层装好了，钩子还没插（正常） |
| 启动游戏 5 秒后进程仍在 | **已就绪** | 插桩层已生成，钩子注册成功（成功标志） |
| 启动后仍是待插桩 | 待插桩 | 看启动日志的「找不到 xxx 的源码」「方法名可能不对」 |

只有「声明了钩子、且它涉及的每个脚本都真的插桩成功」才会翻成已就绪；源码缺失或方法名写错不会翻。

## 7. 打包与发布

```bash
# 1) 生成清单骨架（自动写入 sources）
python tools/jjm_pack.py manifest 我的扩展/ --id me.my_ext --name "我的扩展" --line 4.6

# 2) 静态自检（补丁锚点 / 钩子目标 / 源码声明 / 联机闸门）
python tools/jjm_pack.py check 我的扩展.zip

# 3) 开发者校验准入（与启动器 strict 口径一致）
python tools/jjm_pack.py verify 我的扩展.zip

# 4) 打包
python tools/jjm_pack.py pack 我的扩展/ -o 我的扩展-1.0.0.zip

# 5) 需要「已验证」标记时（开发者版识别）
python tools/jjm_pack.py seal 我的扩展.zip
```

`check` 必须 0 error 再发。`SELF-01` 在 1.7 里会被 `SELF-04` 取代：目标脚本在随包源码里即可，不需要自带原文。

## 8. 安装 / 启用 / 卸载（按线）

| 操作 | 结果 |
|---|---|
| 在 4.6 线导入 | 只写 `overlay-46.pck`；4.7 完全没有这个包 |
| 在 4.6 停用 | 只改 4.6 的启用位；切到 4.7（如果也装了）仍启用 |
| 在 4.6 卸载 | 只删 4.6 的覆盖层；4.7 那份与它的启用状态保留 |
| 同一包再装 4.7 | 需要一份声明 4.7 的包；4.6 的包会被拒绝 |

命令行同样按线：

```bash
python -m app.cli mods list                  # 全部，行首标出装在哪几条线
python -m app.cli mods list --line 4.6       # 只看 4.6 线（启用位/状态/钩子都读这条线）
python -m app.cli mods disable me.my_ext --line 4.6
python -m app.cli mods enable  me.my_ext --line 4.6
```

## 9. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 装到 4.7 被拒「只适配 4.6」 | 跨线安装 | 出 4.7 版清单，不要改 4.6 那份 |
| 装上了但功能没反应 | 钩子方法名写错 / 目标脚本不在源码里 | 看「待插桩」是否变「已就绪」，跑 `check` |
| 补丁锚点命中数不符 | 4.6 本体不是标准版，或锚点抄错 | 用标准 1.45 本体；锚点逐字符核对 |
| 安装报「缺少可用的反解源码」 | 发布包被裁剪 / 源码指纹不符 | 用完整发布包覆盖；或设置反解工程 |
| `sources.sha256` 不一致 | 按别的源码算的锚点 | 用 `manifest` 重新生成，按本线源码重算补丁 |
| 界面「已启用」但进游戏没变化 | 合并层锚点失配 | 启动日志搜「合并层跳过」；开发者版会标红 |
| 一装就黑屏 | `files[]` 铺了原版脚本 / 父类变源码而子类没变 | 删掉脚本覆盖；改用 `text_patches` |
| 卸载后重启还在 | 插桩缓存没清 | 扩展页「清理残留」，或删 `cache/instrumented/` |
| 合集包只装上一部分 | 某个成员失败 | 逐条看日志；1.7 允许部分成功，不会回滚 |
