# 自定义基线接入手册（改版创作者版）

> 适用：把**自己的机甲旋风改版**登记进启动器，让玩家用启动器启动它。
> 相关代码：`app/core/custom_lines.py`、`app/core/identity_gate.py`、
> `app/core/line_desc.py`、`app/core/custom_baseline.py`
> 入门准则（源码交付细节）：`自定义基线导入准则.md`

---

## 0. 一句话

启动器只提供**运行壳 + 接入壳**：执行你的改版、隔离存档、按你交的描述校验能力。
**不逆向、不猜、不替你补源码。**

想在改版上挂 mod，必须额外交「可验收的反解源码基线」；只交一个 exe/pck 也能登记，
但只能启动，不能协商扩展。

---

## 1. 两种形态

| `kind` | 你选的文件 | 启动方式 | 扩展 |
|---|---|---|---|
| `exe` | 改版自带的完整可执行文件 | **直接执行它**，参数原样透传 | 不加载 |
| `pck` | 只有资源包、没有可用 exe | 用**启动器底座引擎**挂载这个 pck | 不加载 |

- `exe` 形态：启动器只负责执行 + 存档隔离，绝不介入资源挂载。
- `pck` 形态：底座 exe + 底座 pck（提供 `project.godot` 与 `_compat`）挂载你的 pck，再切主场景（默认 `res://scenes/start_page.tscn`）。

登记入口：**游戏库 → 管理自定义版本 → 添加**。

---

## 2. 身份闸门：按文件内容自证

登记时启动器会扫描文件内容（`identity_gate.probe`），确认它确实是机甲旋风改版本体：

- 用内置 1.45 正典特征库比对；
- **不采信**你在描述里写的「我是什么版本」；
- 冒名包、别的 Godot 游戏、扩展覆盖层一律拒绝登记。

判定结果（`identity_hash` / `engine_line` / `baseline`）会写进登记记录，并用于
绑定你的 `line.json`。换文件后旧指纹与分档自动失效。

---

## 3. 接入分档

| 分档 | 条件 | 能力 |
|---|---|---|
| `launch-only` | 文件连身份闸门都没过（仅 exe 形态兜底） | 只能启动 |
| `probe-only` | 过了身份闸门，但没有合格的 `line.json` | 启动 + 只读探测；**不挂扩展** |
| `full` | `line.json` 描述校验通过 | 可协商挂载扩展（仍受下面的限制） |

> **1.7 现状**：自定义线的插桩层生成器尚未接入。即使到了 `full`，方法钩子类
> 扩展也会被**明确跳过**（不是静默失败）。纯资源/数据覆盖类扩展仍可用。
> 界面会按分档显示说明，不会让你误以为「扩展丢了」。

---

## 4. `line.json`：描述文件

放在改版本体同目录，随改版一起分发。schema：`schemas/custom_line.v1.schema.json`。

```jsonc
{
  "schema": 1,
  "name": "我的改版",
  "version": "1.0.0",
  "publisher": "你的名字",
  "network": false,
  "identity": {
    "identity_hash": "启动器闸门算出的值（先用启动器登记一次，从记录里取）",
    "engine_line": "4.7",
    "baseline": "jjxf.v1.45"
  },
  "source_index": "sources/index.json",
  "capabilities": [
    { "id": "overlay.mount", "kind": "resource" },
    { "id": "Game.combat_power", "kind": "method",
      "target": "scripts/game.gd", "symbol": "combat_power", "phase": "after" }
  ],
  "anchors": [
    { "id": "hook.combat_power", "file": "scripts/game.gd", "anchor": "func combat_power(" }
  ]
}
```

字段要点：

| 字段 | 说明 |
|---|---|
| `identity.*` | 必须与闸门实测一致；填错即降级 |
| `source_index` | 相对 `line.json` 的索引文件；不得绝对路径 / `..` |
| `capabilities[].kind` | `method` / `signal` / `hook` / `resource` |
| `capabilities[].target` | 脚本路径，如 `scripts/game.gd` |
| `anchors[]` | 声明「这些文本在源码里存在」，用于锚点级校验 |
| `network` | 必须 `false`；填 `true` 直接拒绝 |

### 4.1 校验规则

启动器做三件事：

1. 按 schema 读；
2. `identity.identity_hash` 与闸门对**这个文件**算出的指纹比对；
3. **逐项**验证 `capabilities`（method/signal/hook）与 `anchors` 在 `source_index`
   指向的反解索引里真的存在。

第 3 条不是可选项。只信声明不验证，等于回到「改版玩法与扩展钩子互不相识，硬挂只会崩」。
任何一项不过 → 降级 `probe-only`，原因写进 `access_note`，不阻断启动。

### 4.2 索引格式

```jsonc
{
  "files": ["scripts/game.gd", "scripts/hud.gd"],
  "symbols": { "scripts/game.gd": ["combat_power", "equipment_changed"] },
  "anchors": { "scripts/game.gd": ["func combat_power("] }
}
```

- `symbols` 只认 `func` / `signal` 定义。
- `anchors` 是原文子串，必须逐字符存在。

## 5. 反解源码基线（想支持 mod 就必须交）

交付目录：

```
我的基线/
├─ baseline.json      ← 元数据
├─ index.json         ← 符号/锚点索引
└─ sources/           ← 明文 .gd
    └─ scripts/…
```

`baseline.json`：

```jsonc
{
  "schema": 1,
  "identity_hash": "与 line.json 同一个值",
  "engine_line": "4.7",
  "source_dir": "sources",
  "index": "index.json"
}
```

验收项（B0–B5，全部通过才登记）：

| 项 | 要求 |
|---|---|
| B0 | `baseline.json` 的 `identity_hash` / `engine_line` 与闸门一致 |
| B1 | `sources/` 有明文 `.gd`、UTF-8、非空、含 GDScript 特征 |
| B2 | `index.json` 的 files / symbols / anchors 在源码里逐项查得到 |
| B3 | ≥ **80%** 的源码脚本能在本体 pck 索引里找到对应条目（`.gd` ↔ `.gdc`） |
| B4 | `line.json` 声明的 method/hook 目标脚本必须交了源码 |
| B5 | 源码正文不得命中联机协议规则（ENet/WebSocket/UDP/TCP/DTLS、自建服务端、IP:端口、NAT 穿透等） |

验收通过后写 `config/custom_baselines.json` 登记。`status()` 每次重新核对本体指纹
与源码摘要；**源码被改过就自动失效**，必须重新导入。

> 为什么卡这么严：插桩要往**原脚本明文**里写 `dispatch_before/after`。拿别的版本
> 源码凑数，插桩产物会盖到错误脚本上，表现是黑屏或改动静默失效。B3 的 80% 就是
> 挡这个的。

入口：**设置 → 自定义基线导入**（或「管理自定义版本」里的基线导入）。

## 6. mod 线隔离（为未来预留）

自定义线从第一版起就按 **line id** 隔离存储：

| 对象 | 命名 |
|---|---|
| 线 id | `custom:<uuid>`（配置里的键） |
| 文件名标签 | `paths.line_tag()` → `custom_<uuid>`（冒号在 Windows 非法） |
| 覆盖层（未来） | `packs/<扩展 id>/overlay-custom_<uuid>.pck` |
| 清单副本（未来） | `manifest-custom_<uuid>.v2.json` |
| 启用位（未来） | `lines["custom:<uuid>"].enabled` |

原则：

1. **一条线一份覆盖层**，自定义线之间、自定义线与内置线之间互不覆盖。
2. 线的启用/停用/卸载只影响自己。
3. 未来开放自定义线 mod 时，`line.json` 需要新增「允许挂载」声明；在那之前，
   不要发布声称「支持自定义线」的扩展包。

---

## 7. 常见拒绝原因

| 提示 | 原因 | 处理 |
|---|---|---|
| 「不是机甲旋风本体」 | 内容特征不符 | 确认真的是改版本体；不要拿扩展覆盖层冒充 |
| 「identity_hash 与本体不符」 | `line.json` / `baseline.json` 抄了别的版本 | 用当前文件重新登记取值 |
| 「引擎线判定不一致」 | 描述写 4.7，实测是 4.6 | 改描述 |
| 「符号 xxx 在源码里找不到」 | 索引写了不存在的方法 | 重新生成索引 |
| 「只有 xx% 脚本能在本体找到」 | 源码不是这份改版的 | 换正确的反解工程 |
| 「含联机协议」 | 源码/声明命中联机规则 | 本启动器只做单机，不支持联机 |
| 「描述校验不过，已降级 probe-only」 | 上面任一项 | 看 `access_note`，修完重新登记 |

## 8. 发布清单

- [ ] 本体能被身份闸门识别（不是冒名包）
- [ ] `line.json` 三处 `identity` 与实测一致
- [ ] 索引里的符号/锚点全部能在源码中找到
- [ ] 要支持 mod：`baseline.json` + `index.json` + `sources/` 通过 B0–B5
- [ ] 描述与源码都没有联机协议
- [ ] 包内没有启动器文件、没有别人的扩展
- [ ] 发布说明写清：启动器版本要求、分档（launch-only / probe-only / full）、
      是否支持 mod、存档目录名
