# 给 AI 的使用说明（扩展开发文档 1.7）

> 你正在帮用户做《机甲旋风》启动器的扩展或改版接入。**先读完这份，再动文件。**
> 本目录是自包含的：文档 + `tools/` + `baseline/` 一起用，不要只拿其中一个文件。

---

## 0. 先问清三件事

1. **哪条线？** 4.6（1.45 原版）还是 4.7（剧情版）？两条线的源码、锚点、清单、
   安装目录、启用状态全部独立，**不能混**。
2. **做什么？** 普通扩展 / 4.7 剧情 mod / 自定义基线接入 / 自定义线扩展。
3. **手上有源码吗？** 普通扩展作者不需要原版源码（启动器随包带
   `baseline/sources-<line>.zip`）；改版创作者必须自备并交付反解源码。

---

## 1. 三条硬规则（违反会直接失败）

### 1.1 一条线一份包

- 4.6 的包只能装 4.6，4.7 只能装 4.7；跨线安装是**硬拒绝**。
- 要两线支持 → 两份清单（`manifest-46.v2.json` + `manifest-47.v2.json`）+ 共用载荷。
- 同一包在两条线的覆盖层/启用状态/卸载互不影响。

### 1.2 用了补丁或钩子就必须声明源码

```jsonc
"schema": 4,
"sources": { "name": "sources-4.6.zip", "sha256": "…", "line": "4.6" }
```

- schema 4 没写 → 拒装；
- `sha256` 与本机随包源码不一致 → 拒装；
- 不要手抄哈希：`python tools/jjm_pack.py manifest <目录> --id <id> --name <名字> --line <线>`。
- **不要**把原版 `scripts/*.gd` 打进包当基底——启动器会自动兜底，打进去反而覆盖基线。

### 1.3 「待插桩」不是故障

- 首次导入显示「待插桩」= 文件装好了、钩子还没插（插桩在启动时做）。
- 启动游戏、进程稳定 5 秒后自动变「已就绪」= 钩子注册成功。
- 启动后仍是「待插桩」→ 看启动日志：目标脚本不在源码里 / 方法名写错 / 源码指纹不符。

## 2. 标准流程

```bash
# 1) 选线，生成清单（自动写 sources）
python tools/jjm_pack.py manifest 我的扩展/ --id me.my_ext --name "我的扩展" --line 4.6

# 2) 填 files / data_patches / text_patches / method_hooks

# 3) 静态检查：锚点命中数、钩子目标、源码声明、联机闸门
python tools/jjm_pack.py check 我的扩展.zip --line 4.6

# 4) 严格档准入（与启动器 strict 一致）
python tools/jjm_pack.py verify 我的扩展.zip --line 4.6

# 5) 打包 / 封验证标记
python tools/jjm_pack.py pack 我的扩展/ -o 我的扩展-1.0.0.zip
python tools/jjm_pack.py seal 我的扩展-1.0.0.zip
```

4.7 把 `--line 4.6` 换成 `--line 4.7`。**不要**用 4.6 的锚点直接跑 4.7。

## 3. 各改法的优先级

| 优先级 | 方式 | 何时用 | 注意 |
|---|---|---|---|
| 1 | `files[]` | 加自己的文件 / 换资源 | **禁止**铺 `scripts/*.gd` |
| 2 | `data_patches[]` | 改 JSON 里的值 | 带 `expect` 断言旧值 |
| 3 | `text_patches[]` | 改脚本文本 | 锚点必须按本线源码重算 |
| 4 | `method_hooks[]` | 挂到方法上 | 方法名写错不报错，只是不触发 |

`text_patches` 的铁律：

- `find` 在范围内恰好出现 `expect_count` 次（默认 1）；
- 缩进逐字符一致（Tab）；
- `find` / `replace` 一起改；
- 不唯一时用 `"scope": "function:xxx"`。

## 4. 4.7 特别提醒

- 4.7 是剧情版：`scripts/hud.gd` 从 18 KB 变 32 KB，函数体整段重写。
- 4.7 的源码层是 **剧情覆盖层 + `sources-4.7.zip`**，剧情层优先。
- 剧情 mod 替换的是剧情覆盖层（`.pck`，741 条左右），不是普通扩展；
  挂载顺序 `baseline → story → mod → sources → merged → instrumented`。
- 换剧情包会让按旧剧情源码算的补丁失配——发布说明要写清适配的剧情版本。
- 标准本体指纹：**380,259 条目 / 3,066,540,271 字节**；不是这个会被源码指纹拦下。

细节见 `4.7-mod/4.7-mod开发规范.md`。

## 5. 交付前自检

- [ ] `check` 0 error，`verify` 通过
- [ ] 清单 `schema=4`，`sources` 三字段齐全且 sha256 匹配
- [ ] 每一条 `text_patches` 的锚点都在本线源码里唯一命中（`expect_count` 对得上）
- [ ] 钩子目标方法在源码里真实存在
- [ ] 在标准本体上实测：导入 → 启动 → 待插桩变已就绪 → 功能生效
- [ ] 只卸当前线不影响另一条线
- [ ] 没有游戏本体 / 引擎 / 反解工程 / 联机协议 / 绝对路径

## 6. 遇到报错先看哪里

| 错误码 | 文档 |
|---|---|
| `MAN-*` / `SRC-*` / `SELF-*` / `PATCH-*` / `HOOK-*` | `公共文档/扩展打包与发布手册.md` §6 |
| 装上了没反应 | 对应线规范「常见坑」；启动日志搜「插桩」「合并层跳过」 |
| 自定义线登记失败 | `公共文档/自定义基线接入手册.md` §7 |
| 自定义线 mod | `公共文档/自定义基线扩展开发手册.md` |

不要靠猜改代码：先跑 `check`，它会把「哪个文件、哪条补丁、哪个锚点」打出来。
